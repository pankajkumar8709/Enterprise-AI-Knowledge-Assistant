# Enterprise AI Knowledge Assistant — Technical Overview

## Introduction

The Enterprise AI Knowledge Assistant is a secure, scalable backend platform that enables organizations to manage enterprise knowledge and build AI-powered question-answering capabilities. It is built using FastAPI, PostgreSQL, SQLAlchemy, Alembic, JWT authentication, and role-based access control.

The system is designed to evolve into a complete Retrieval-Augmented Generation (RAG) system capable of processing enterprise documents, retrieving relevant information, and generating context-aware responses using Large Language Models.

## Architecture

The backend follows a layered architecture:

- **API Layer**: FastAPI REST endpoints organized into route groups for Auth, Users, Documents, Knowledge, Chat, Search, Admin, and Departments.
- **Service Layer**: Business logic for document ingestion, text extraction, chunking, embedding generation, retrieval, and LLM answer generation.
- **Data Layer**: SQLAlchemy ORM with PostgreSQL, managed by Alembic migrations.

## Authentication and Authorization

The system uses JWT (HS256) tokens for authentication. Tokens expire after a configurable period (default 30 minutes). Refresh tokens are supported with a 7-day expiry.

Role-based access control (RBAC) supports two primary roles:
- **admin**: Full access to all documents, users, and system management.
- **employee**: Access limited to documents visible to their department or marked as visible to all.

Document-level access control uses a `visibility` field (`all` or `department`) combined with department ACL lists on documents, chunks, and knowledge objects.

## Document Management

Documents can be uploaded in the following formats: PDF, DOCX, PPTX, TXT, and Markdown.

The ingestion pipeline processes documents through these stages:
1. **Upload**: File is validated (magic bytes, SHA-256 deduplication, size limit 25 MB).
2. **Extraction**: Text is extracted using pypdf (PDF), python-docx (DOCX), python-pptx (PPTX), or direct read (TXT/MD). OCR fallback is available for scanned PDFs using pytesseract.
3. **Chunking**: Extracted text is split into token-aware chunks (target 500 tokens, max 700, min 60, overlap 80).
4. **Embedding**: Each chunk is embedded using the BAAI/bge-small-en-v1.5 sentence-transformer model (384 dimensions), stored as pgvector in PostgreSQL.

## Knowledge Objects (OKF)

The Open Knowledge Framework (OKF) stores structured knowledge as typed objects with attributes, relations, and versioning. Knowledge objects go through an admin review workflow: `pending_review` -> `approved` or `rejected`. Bulk review is supported.

## Retrieval Pipeline

When a user asks a question, the system:
1. **Classifies** the query as `chunk`, `okf`, or `mixed` using the LLM classifier.
2. **Rewrites** the query for better retrieval using the LLM query rewriter.
3. **Retrieves** relevant chunks via vector similarity search (pgvector cosine distance) and full-text search (PostgreSQL tsvector), fused using Reciprocal Rank Fusion (RRF).
4. **Retrieves** relevant OKF knowledge objects via keyword and semantic matching.
5. **Merges** results and selects the top 6 context items.

## LLM Answer Generation

The system uses the Groq API with the `llama-3.3-70b-versatile` model to generate answers. The answer pipeline:
1. Builds a prompt with the retrieved context (chunks as labelled passages, OKF facts as key-value pairs).
2. Calls the LLM with retry logic (exponential backoff on 429/5xx).
3. Parses citation markers `[S1]`, `[S2]`, etc. from the answer.
4. Computes a confidence score: `0.7 * top_cited_score + 0.3 * min(1, n_cited/2)`.
5. Persists the conversation, messages, and message sources to the database.

If the LLM returns `INSUFFICIENT_CONTEXT`, the system returns a fallback message: "I couldn't find this in the company knowledge I have access to."

## Chat API

The Chat API provides:
- `POST /api/v1/chat/conversations` — Create a new conversation.
- `GET /api/v1/chat/conversations` — List conversations for the current user.
- `GET /api/v1/chat/conversations/{id}` — Get a conversation with its messages.
- `DELETE /api/v1/chat/conversations/{id}` — Delete a conversation.
- `POST /api/v1/chat/conversations/{id}/messages` — Send a message and receive an AI-generated answer.

## Health Checks

- `GET /api/v1/health` — Liveness check, always returns `{"status": "ok"}`.
- `GET /api/v1/health/ready` — Readiness check, returns 503 if the database is unreachable.

## Security Features

- JWT authentication with role re-read per request (revocation support).
- Active-user revocation: deactivated users cannot authenticate.
- Document-level and department-level ACL.
- Audit logging for auth, document, and knowledge events.
- CORS restricted to configured origins.
- X-Request-ID request tracing.
- SHA-256 deduplication prevents duplicate document uploads.
- Magic-byte file validation prevents MIME type spoofing.

## Deployment

The application is started with:

```
uvicorn app.main:app --host 0.0.0.0 --port 8000
```

Database migrations are applied with:

```
alembic upgrade head
```

Embeddings for existing chunks can be backfilled with:

```
python -m app.cli backfill-embeddings
```
