## 6. Behavior as built (key mechanics)

**Upload** → extension check only (`.pdf .docx .pptx .txt .md .markdown`) → streamed write to `storage/documents/{uuid}{ext}` with 10 MB cap (reject 400, partial deleted) → insert row (`status=uploaded`) → **synchronously** runs extraction **and** chunking inside the request (response already contains final states). No sha256, no magic bytes, no duplicate detection, no Celery, no audit event.

**Extraction** (`services/extraction.py`, pypdf/zipfile+ElementTree/encoding-ladder): whole-document OCR fallback only if NO page yielded text (requires `pdftoppm` + `tesseract`, else clear ExtractionError → `failed`). Header/footer removal: first/last line of a page removed if seen ≥2 times (any page count). Cleaner: NFKC-ish whitespace normalize, strip control/zero-width, **delete every char outside ASCII-printable + U+00A0–U+024F** (removes ₹, —, “”, emoji, CJK/Devanagari), drop all-punctuation lines and `page N [of M]` lines. Output: single text blob (raw.txt, clean.txt) — **no per-page structure**. Non-`ExtractionError` exceptions (EmptyFileError, PdfReadError, FileNotDecryptedError) propagate → HTTP 500, row left `extraction_status=processing`.

**Chunking** (`services/chunking.py`): sizes in **characters** (default target 800, overlap 120, per-request override 100–5000 / 0–1000); by default runs **all three strategies** (fixed_size, sentence_based, section_based) and stores **three overlapping chunk sets** for the same document, each with `chunk_index` restarting at 1. Section detection = heuristic heading line (`#…`, `1.1…`, ALL-CAPS ≤10 words, `…:`, Title Case ≤6 words). Page numbers: PDF only, by matching first 200 chars of each pypdf page text inside cleaned text, fallback sequential guess; non-PDF → page 1. No token counting (`text_length` = chars), no min-size merge (trailing chunks as small as 14 chars observed).

**Knowledge extraction** (`services/knowledge.py`): **regex heuristics, no LLM** — patterns `Q:/A:`, `Department:/Dept:`, `Employee:/Title:/Manager:`, `Product:/Asset:`, and any line ≥12 chars matching `\b(must|should|shall|required|not allowed|prohibited|only)\b` → business_rule. Required payload fields (code): policy{title}, employee{full_name}, department{name}, product{name}, faq{question,answer}, business_rule{rule}, asset{name}. `canonical_key = type + ":" + slug(lower, non-alnum→-)`. Versioning: same (object_key, source_document_id) + changed payload → old row `is_current=false`, new `object_version+1` (same table, no history table). Re-extraction is row-idempotent (verified: 2 → 2 → 2 rows). No status/review, no confidence, no quote/chunk/page link, no ACL, no unique live key, relations = free-text predicates with `target_name` only (no FK). Search: `ILIKE %q%` over name/payload/summary/source_excerpt.

**Auth:** JWT HS256 claims `{sub=email, role, exp, iat, jti}`; bcrypt cost 12; role re-read from DB each request + `is_active` check (verified: token minted as employee acted as admin after DB role update; expired/tampered/alg-none/garbage → 401); password policy ≥10 chars + ≥1 uppercase + ≥1 digit; duplicate email case-insensitive → 409; identical 401 body for unknown email vs wrong password; signup ignores client `role`. No refresh tokens, no logout, no rate limits.

**Storage:** uploads `storage/documents/*` (no static mount → never served by app); extractions `storage/extractions/{doc_id}/*`. Delete removes DB rows (chunks + knowledge via cascade/manual), stored file, extraction dir — verified zero orphans in test run; knowledge objects are **hard-deleted**, not archived.

**Tests:** 14 tests, all passing, **87% line coverage** of `app`, run against **SQLite** (`test_phase1.db`), not PostgreSQL. No unit tests for cleaner/chunker/OKF-validator/auth-attacks; no golden-path E2E file; fixtures directory absent.
